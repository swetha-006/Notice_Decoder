Notice Check Architecture & Code Map

A reference guide to the core modules, security boundaries, and data paths in the Notice Check codebase.

1. The Four-Stage Verification Pipeline

Stage 1: In-Browser PII Redaction & Token Mapping

Code location: lib/redact.ts · Component: components/RedactionPreview.tsx

Regex patterns and heuristics identify names, phone numbers, emails, PANs, Aadhaar numbers, bank account numbers, IFSC codes, and addresses. Replaces matches with stable tokens ([PERSON_1], [PAN_1]). Raw data is retained strictly in browser memory.

Stage 2: Deterministic Fraud Signal Engine

Code location: lib/signals.ts · Allowlist: lib/official-domains.ts

Runs offline-capable heuristics checking for UPI handles (@okaxis, etc.), crypto addresses, gift card demands, threat language ("arrest warrant", "frozen"), lookalike typosquatting domains (Levenshtein distance ≤ 2), and deadline math.

Stage 3: Protected Server Route & Structured AI Analysis

Code location: app/api/analyze/route.ts · Schema: lib/schema.ts

Receives masked text only. Applies in-memory IP rate limiting (10 req/min/IP). Prompts Google Gemini (model via GEMINI_MODEL) with strict JSON output schema. Retries once on invalid JSON, with a deterministic fallback if the API key is not configured.

Stage 4: Verbatim Grounding, Composite Scoring & Local Rehydration

Code location: lib/grounding.ts & lib/scoring.ts · Viewers: components/DocumentViewer.tsx, components/ResponseDraft.tsx

Cross-examines model quotes against the original notice. Drops hallucinated flags. Merges non-overlapping character spans. Computes a deterministic final score and verdict. Restores original user PII into the drafted formal reply locally.
